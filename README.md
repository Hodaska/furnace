# Промышленная печь

Система управления и мониторинга промышленной печи на базе Docker Compose.

## Архитектура

| Сервис | Описание | Порт |
|--------|----------|------|
| **math-model** | Математическая модель печи (Go + OPC UA). Симулирует нагрев/охлаждение | 4840, 8888 |
| **openplc** | ПЛК (OpenPLC Runtime). Логика аварийного отключения при T >= 100°C | 502, 8080 |
| **node-red** | Оркестратор. Связывает все сервисы, предоставляет UI управления | 1880 |
| **influxdb** | База данных временных рядов. Хранит температуру, мощность, аварии | 8086 |
| **grafana** | Визуализация и алертинг. Дашборд + уведомление при аварии | 3000 |

### Поток данных

```
Node-RED (каждую секунду)
  → GET температуры с math-model
  → записывает в ПЛК по Modbus TCP
  → читает аварийный сигнал из ПЛК
  → при аварии останавливает печь
  → всё пишет в InfluxDB

Grafana
  → читает данные из InfluxDB
  → отображает графики
  → отправляет алерт при T >= 100°C
```

### Модель печи

- Вход: мощность ТЭНа (0–100%)
- Выход: температура (°C)
- При включении: плавный нагрев до 300°C (инерция 120 сек)
- При выключении: медленное остывание до 20°C (инерция 30 сек)
- При достижении 100°C: автоматическое аварийное отключение

## Отличия от технического задания

### 1. SCADA: Grafana + Node-RED вместо RapidSCADA

**ТЗ:** развернуть SCADA RapidSCADA, отрисовать систему управления с кнопкой старт и отображением состояния.

**Сделано:** панель управления (кнопки СТАРТ/СТОП) реализована как HTTP endpoint в Node-RED, визуализация и алертинг — в Grafana.

**Обоснование:** RapidSCADA не имеет официального Docker-образа и требует сложной ручной настройки схем через проприетарный редактор без возможности автоматического развёртывания. Связка Node-RED + Grafana обеспечивает идентичный функционал: управление кнопками, отображение состояния ПЛК и мат. модели, алерты — при полностью автоматическом запуске одной командой `docker compose up`.

### 2. Протокол мат. модели: HTTP вместо OPC UA (в части Node-RED)

**ТЗ:** протокол мат. модели — OPC UA.

**Сделано:** мат. модель поднимает OPC UA сервер (порт 4840) согласно ТЗ, однако Node-RED взаимодействует с ней через HTTP REST API (порт 8888).

**Обоснование:** пакет `node-red-contrib-iiot-opcua` в актуальных версиях Node-RED имеет нестабильную работу в контейнерной среде (конфликты зависимостей, падения при старте). HTTP API обеспечивает ту же функциональность без потери надёжности, OPC UA сервер в мат. модели присутствует и доступен для внешних клиентов.

## Требования

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- [Git](https://git-scm.com/)

## Запуск

```bash
git clone https://github.com/Hodaska/furnace.git
cd furnace
docker compose up --build
```

Первый запуск занимает ~10 минут (сборка образов).

## Интерфейсы

| Интерфейс | Адрес | Логин |
|-----------|-------|-------|
| Grafana (главный дашборд) | http://localhost:3000 | admin / admin |
| Node-RED UI (кнопки СТАРТ/СТОП) | http://localhost:1880/ui | — |
| OpenPLC (веб-интерфейс ПЛК) | http://localhost:8080 | openplc / openplc |
| Node-RED (редактор потоков) | http://localhost:1880 | — |

## Остановка

```bash
# Остановить
docker compose down

# Остановить и удалить все данные
docker compose down -v
```
